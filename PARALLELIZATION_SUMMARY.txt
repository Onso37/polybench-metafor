OVERVIEW
--------
All 30 Fortran benchmark files in this suite have been annotated with OpenMP
directives using the Fortran sentinel syntax (!$OMP). A total of 67
!$OMP PARALLEL DO regions were added across 28 files. Two files were left
sequential by necessity (see "Sequential Benchmarks" below).

To compile with OpenMP support, add the appropriate flag to your Fortran
compiler invocation:
  - GFortran :  gfortran -fopenmp ...
  - Intel ifort:  ifort -qopenmp ...
  - Cray ftn  :  ftn -h omp ...

The compile.sh script may need to be updated to include the OpenMP flag.

--------------------------------------------------------------------------------
PARALLELIZATION STRATEGY
--------------------------------------------------------------------------------

Three main strategies were applied depending on the algorithm:

  1. EMBARRASSINGLY PARALLEL LOOPS
     The outermost loop over independent data (typically "do i = 1, N") was
     decorated with !$OMP PARALLEL DO. Loop indices and scalar temporaries
     were listed in PRIVATE clauses. SCHEDULE(STATIC) was used throughout
     for predictable, balanced work distribution.

  2. SEQUENTIAL OUTER LOOP — PARALLEL INNER LOOPS
     For algorithms whose outer loop carries a dependence (LU, Gramm-Schmidt,
     Cholesky, Durbin, etc.), only the inner loops that are demonstrably
     independent were parallelized. A new parallel region is created on each
     outer-loop iteration.

  3. RACE-CONDITION RESTRUCTURING
     A few kernels (atax, bicg) had a fused loop whose inner update wrote to
     a shared output vector, creating a race when the outer loop ran in
     parallel. These were split into two separate loops:
       - A parallel loop computing the intermediate vector (no races).
       - A second parallel loop with the loop nest transposed so each thread
         owns a unique output element.

OpenMP clauses used:
  PRIVATE(...)      — loop indices and scalar temporaries local to each thread
  REDUCTION(+:var)  — scalar accumulations (e.g. dot-product style sums)
  SCHEDULE(STATIC)  — static equal-chunk assignment of iterations to threads

--------------------------------------------------------------------------------
SEQUENTIAL BENCHMARKS (no parallelism possible)
--------------------------------------------------------------------------------

trisolv.F90
  Algorithm: Forward triangular solve — x(i) = (c(i) - sum_{j<i} A(j,i)*x(j))
             / A(i,i).  Each x(i) depends on all previously computed x(j),
             making the outer "do i" loop inherently sequential. No safe inner
             loop parallelism exists either.

seidel-2d.F90
  Algorithm: 2-D Gauss-Seidel stencil — each cell a(j,i) is updated using
             already-updated neighbors from the same sweep (a(j-1,i),
             a(j,i-1), etc.). This creates loop-carried dependences in both
             the i and j dimensions within a single time step, making both
             spatial loops sequential. A wavefront (anti-diagonal) or
             red-black decomposition would be required to expose parallelism,
             but that would change the algorithm semantics.
